# shared/vectors — 语言中立测试向量

> **这一层是两端行为一致性的机器保证**：iOS 的纯 C 核心与 Android 的 Java 核心
> 必须对同一份向量得出**相同结论**。改行为 = 先改向量。

## 文件

| 文件 | 内容 | 断言数 |
|---|---|---|
| `bssid-map.json` | 映射：归一化、格式跟随、规则匹配与优先级、default、nil 语义、容量与校验 | 61 |
| `auth-gate.json` | 授权闸：字段缺失/占位符/空白、constraints、scope.mode、进程匹配、短路顺序、静态契约表 | 49 |

## 为什么需要它（而不是只留 C 单测）

对比 R12 之前的 92 条 C 断言，向量解决了三件事：

1. **语言中立**：C 单测把「输入 → 期望输出」写死在 C 代码里，Java 端没法复用；
   向量把同一批事实变成 JSON 数据，两端各写一个薄驱动即可。
2. **一处改、两端同时被约束**：行为变更必须落到向量上，否则两端各自的单测
   仍会「各自通过」——这正是双端化最容易出的漂移。
3. **Android 可直接消费**：Java 侧不需要理解 iOS 的实现，只需满足这些取值。

## 执行机制

```
shared/vectors/*.json  --(jq 转 USV 流)-->  ios/tests/host/vector_rules.c -> ios/hooks/BGGhostRules.c
                                            ios/tests/host/vector_auth.c  -> ios/hooks/BGGhostAuth.c
```

- 入口：`bash ios/tests/host/run-vectors.sh`（已并入 `ios/tests/host/run.sh`）；
- C 端没有 JSON 解析器，因此由 `jq` 把向量转成 **USV（`0x1f` 分隔）**流；
  用 `0x1f` 而不是 TAB，是因为 TAB 属于 IFS 空白类、连续时会被折叠，
  无法区分「空串」与「NULL」——而本向量里「空串 = 不限制」是有意义的取值；
- 记号：`@null@` = NULL，`@empty@` = 空串，`-` = 无期望值，`*` = 该字段不断言。

## 与 C 单测的关系（不是二选一）

| 层 | 管什么 | 位置 |
|---|---|---|
| **向量** | 两端**必须一致的行为** | `shared/vectors/` |
| C 单测 | 向量之外、**C API 机制细节**：透传时不得写入输出缓冲、`cfg == NULL` 不崩溃、静态表完整性 | `ios/tests/host/test_bgg_*.c` |

R13 之后主机侧断言 **141 → 251 条**（新增 110 条向量断言），覆盖只增不减。

## 纪律

- **改行为先改向量**，再改实现；只改实现不改向量 = 破坏双端一致性。
- 向量的期望值必须**语义上正确**，不能是「跑出来的值」。
  R13 抓到过一次自己的错误：初稿写了「SSID 为 NULL → 添加失败」，
  读实现后确认 `ssid == NULL` 的语义是「不限制 SSID」，属**合法**输入，已改正。
- 新增用例必须**可被证伪**：`run-vectors.sh` 的失败路径已做故障注入验证
  （改错一个期望值、反转一条判定，都会被抓住并打印 got/want）。
