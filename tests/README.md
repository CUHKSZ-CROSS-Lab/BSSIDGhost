# 测试矩阵

## 验证目标

确认 Hook 生效，且**只**改变了 BSSID 返回值 —— 不影响真实网络连接。

## 用例矩阵

| # | 用例 | 操作 | 期望结果 | 状态 |
|---|---|---|---|---|
| T1 | Hook 加载 | 启动目标 App，查日志 | 出现 `[BSSIDGhost] 启用` | 待测 |
| T2 | BSSID 替换 | App 内查看 Wi-Fi 信息 | 读到 `11:22:33:44:55:66` | 待测 |
| T3 | SSID 不变 | 同上 | 仍为 `Office_WiFi` | 待测 |
| T4 | 真实链路 | 断开/重连、访问网络 | 网络功能完全正常 | 待测 |
| T5 | 格式一致 | 对比伪造值与真实值格式 | 大小写、分隔符一致 | 待测 |
| T6 | 多次调用 | 反复触发读取（前台/后台切换） | 每次返回均为伪造值 | 待测 |
| T7 | 无规则透传 | 切到未配置的网络 | 返回真实 BSSID，行为不变 | 待测 |
| T8 | 作用域 | 在非目标 App 中检查 | Hook 不生效 | 待测 |
| T9 | 授权闸 | 清空 targets.json 授权字段 | Hook 拒绝启用并记录原因 | 待测 |
| T10 | 交叉校验 | 观察 App 是否有异常上报 | 无风控拦截 / 无异常提示 | 待测 |

## 关键对照组

- **真实设备实测值**：设置 → 无线局域网 → 当前网络详情，记录真实 BSSID。
- **Hook 后 App 读取值**：通过 Frida 或 App 界面读取。
- 两者必须符合配置映射，且 T3 的 SSID 两侧一致。

## 反面用例（必须验证）

- **伪造值格式错误**（小写/换分隔符）→ App 应无法识别或直接失败，用于确认 App 是否做格式校验。
- **只 Hook 单通道** → 若 App 同时调用多个接口，观察是否触发不一致告警（对应 tech-chain.md 第 6 节）。

## 记录要求

每次测试记录：设备型号、iOS 版本、越狱类型、目标 App 版本、真实 BSSID、伪造 BSSID。
